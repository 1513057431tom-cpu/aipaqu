# 实施路线

实施以“可验证的业务闭环”为主线。每个阶段完成后必须通过自动测试、构建检查和人工验收，才能扩大数据源或业务范围。

## 阶段 0：产品与工程基线

- [x] 明确通用物料与供应情报定位。
- [x] 明确内部经营数据和外部网站信号联合输入。
- [x] 明确规则计算、AI 解释和人工决策边界。
- [x] 定义日报结构化快照以及周报/月报聚合规则。
- [x] 定义架构、数据模型、API、工作流、前端和安全基线。
- [x] 建立 FastAPI、Nuxt、Docker Compose、测试和健康检查骨架。
- [x] 实现登录会话和 `ResearchBrief` 试验闭环。
- [ ] 用户评审并确认新的领域基线与首批数据样本。

验收：能够用一组内部样本和一组外部页面解释完整数据流、实体、接口、页面、状态和人工责任边界。

## 阶段 1：内部数据与主数据 MVP（核心闭环可运行）

- 实现 `Material`、`Supplier`、`SupplierMaterial` 和别名实体及迁移。
- 实现 Excel/CSV 导入、文件隔离、查毒状态、字段识别和错误行报告。
- 支持物料、供应商、库存、消耗、需求和在途订单标准 Schema。
- 实现字段映射版本、单位换算、业务时间和导入幂等。
- 实现物料列表、物料详情、供应商和数据导入页面。
- 在 Dashboard 展示数据新鲜度、覆盖率和导入异常。

验收：使用真实匿名样本完成一次导入；相同文件重试不重复生成快照；物料详情能够联合展示库存、消耗、需求和在途。

## 阶段 2：定向外部监控 MVP（核心闭环可运行）

- 实现 `Source`、`CollectionJob`、`Document`、`ExternalSignal` 和证据存储。
- 实现 HTTP 静态页采集、定时调度、内容摘要、页面差异和失败重试。
- 实现价格、规格、可用性、交期和供应商事件的规则抽取与 AI 辅助抽取。
- 实现物料/供应商候选映射、置信度和人工确认队列。
- 实现外部来源、采集记录、页面差异、信号列表和信号详情页面。
- 用 `CrawlPolicy` 限制域名、频率、并发、超时和页面数量。

首轮只支持 20 至 50 个用户指定的公开或已授权 URL。浏览器动态页面、RSS 和开放 API 可按真实来源需求增量加入，但不能扩大为全网爬虫。

验收：连续运行两周，能稳定识别页面变化；每条正式信号都能回到原始证据；重复采集不产生重复信号；访问挑战进入可解释人工状态。

## 阶段 3：每日情报与采购建议 MVP（核心闭环可运行）

- 实现 `DailyIntelligenceSnapshot`、`PlanningParameterVersion`、`ProcurementRecommendation` 和 `RecommendationDecision`。
- 实现内部数据与外部信号的数据新鲜度、完整性和单位校验。
- 实现版本化 `PlanningEngine`，首批规则覆盖库存可支撑天数、预计缺料、积压、建议下单日、最晚下单日和建议数量。
- 应用在途、安全库存、交期、最小订购量和订购倍数。
- 保存输入摘要、计算中间量、算法版本、原因码和证据引用。
- 实现采购建议列表、详情、批准、调整、拒绝和导出。
- AI 只生成解释与摘要，不能覆盖规则计算字段。

验收：相同输入、参数和算法版本得到相同建议；每个数字可追溯；数据过期或单位冲突时阻止正式建议；人工调整保留原始值和原因。

## 阶段 4：周期报告闭环（已完成首版）

- [x] 用框架中立的报告服务连接每日情报快照和采购建议。
- [x] 实现日报草稿、引用、人工审核和快照固化。
- [x] 实现周报/月报对已批准日报结构化快照的确定性聚合。
- [x] 缺少日报时返回缺失日期并停止创建，不启动浏览器或内部同步。
- [x] 实现报告正文编辑、不可变人工版本、Markdown 和 DOCX 导出。
- [x] 保留 `ResearchBrief` 作为自定义专题分析，不作为首页主流程。
- [ ] 增强趋势/异常图表、章节级重生成、版本比较和三栏证据编辑器。

验收：从内部导入和外部采集生成日报；周报/月报只消费日报结构化快照；人工修改不会被非目标章节重生成覆盖；导出内容和引用一致。

## 阶段 5：连接器与采集增强

- 按试点客户优先级实现 ERP、MES、WMS 和数据库只读连接器。
- 增加 RSS、开放 API、Playwright 授权登录态和复杂站点适配器。
- 实现 `BrowserRuntimeProvider`、`SiteAdapter`、浏览器 Profile 加密引用和采集调试工作台。
- 实现 `AccessGrant`、`AccessChallenge` 和 `ManualVerificationSession`。
- 实现正文分块、Elasticsearch 检索和自定义专题分析证据池。

验收：连接器游标可恢复且不丢不重；登录失效、验证码、付费墙、403/429 和站点禁止时进入可解释失败状态，仅由授权或人工接管合法处理。

## 阶段 6：分析与交付增强

- 多仓库、多单位、多供应商分配和场景模拟。
- 供应商绩效、价格趋势和需求预测，但保留可解释基线与人工审核。
- ECharts 数据集快照、图表编辑和来源映射。
- PDF、SMTP 和企业协作工具通知。
- 经独立审批的采购建议导出或受控写回接口。

验收：高级模型可以与规则基线比较；图表数字可追溯；消息幂等重试不重复投递；写回权限与只读连接完全隔离。

## 阶段 7：系统验证与商业化准备

- 单元测试：单位换算、日期、快照、信号去重、建议公式、状态机和权限。
- 契约测试：连接器、采集器、PlanningEngine、模型供应商和工作流执行器。
- 集成测试：MySQL、Redis、Elasticsearch、文件存储和外部服务假实现。
- E2E：导入内部数据、采集外部页面、审核建议、生成日报和聚合周报。
- 安全测试：CSRF、CORS、SSRF、恶意文件、提示注入、权限越界和秘密泄露。
- 恢复测试：Worker 中断、连接器游标、模型失败、凭据失效和 Redis 重启。
- 容量测试：按工作空间、物料、来源、日快照和任务量逐级压测，记录水平扩展边界。

最终完成标准：产品需求中的每项 MVP 验收都有自动测试或可重复的人工验证证据，且不依赖某个 Agent 框架的私有对象或商业授权。
