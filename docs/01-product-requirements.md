# 产品需求：通用物料与供应情报平台

## 1. 产品目标

为制造企业提供一个独立于 ERP、MES、WMS 的通用情报层，持续联合内部经营数据与外部网站信息，识别物料、库存、价格、供货和供应商变化，生成可解释、可追溯、可由人工调整的采购建议、告警和周期报告。

产品不替代企业现有交易系统。核心价值是把分散信息转化为统一的物料与供应商视图，并让每条变化、建议和报告结论都能回到内部快照或外部证据。

## 2. 目标用户

- `ADMIN`：配置用户、数据连接、采集凭据、模型、规则版本和系统参数。
- `EDITOR`：维护物料映射、配置外部监控、审核信号、处理采购建议、编辑和审核报告。

首版面向单工作空间，不实现商业化多租户、套餐和计费。行业特有字段和规则作为后续扩展，不进入通用核心。

## 3. 首版实施策略

首版优先跑通一个“内外部数据联合产生可执行情报”的最小可信闭环：

```text
登录
  → 导入物料、供应商、库存、消耗、需求和在途订单
  → 配置并定时采集外部页面
  → 将外部变化映射到物料或供应商
  → 生成每日结构化情报快照
  → 计算缺料、积压、采购时间和数量建议
  → 人工审核、调整或拒绝
  → 生成日报 / 周报 / 月报并导出
```

首版内部数据入口以 Excel/CSV 为主，同时预留 ERP、MES、WMS 和数据库连接器接口。外部采集聚焦 20 至 50 个用户指定的公开或已授权页面，不做无边界全网爬取。

## 4. 核心使用场景

### 4.1 接入内部经营数据

用户可以上传 Excel/CSV，或通过只读连接器同步：

- 物料编码、名称、规格、单位、分类和别名。
- 供应商、供应商物料编码、最小订购量、订购倍数和参考交期。
- 分仓库存、可用库存、预留量和质检冻结量。
- 历史消耗、生产计划、预测需求和安全库存参数。
- 采购订单、已收数量、剩余在途数量和预计到货日期。

每次导入或同步必须生成可重放的数据快照，保存来源系统、业务时间、同步时间、字段映射版本、校验结果和内容摘要。首版默认只读，不向企业系统回写库存或订单。

### 4.2 配置外部数据获取

用户按物料、供应商或监控主题配置来源：

- 供应商官网、产品页和公告页。
- 行业或原材料价格页面。
- 市场平台中的商品、规格和供货页面。
- 新闻、企业公告和用户指定站点。
- RSS 和开放 API。

每个来源必须配置访问方式、采集频率、允许范围、内容抽取规则和绑定对象。采集结果保存页面快照、时间、状态码、内容摘要和差异，并抽取以下结构化信号：

- `PRICE`：价格、币种、单位和变化幅度。
- `SPECIFICATION`：规格、型号或包装变化。
- `AVAILABILITY`：有货、缺货、停产或恢复供应。
- `LEAD_TIME`：交期或发货周期变化。
- `SUPPLIER_EVENT`：供应商公告、产能、停工、并购等事件。

系统不绕过验证码、付费墙、登录权限和其他访问控制。需要身份的来源必须使用用户授权凭据；遇到访问挑战时暂停自动采集并进入人工接管流程。

### 4.3 统一物料与供应商映射

系统使用物料编码、名称、规格、单位、供应商物料编码和别名生成候选匹配。AI 可以解释候选关系，但低置信度或冲突匹配必须由用户确认。

映射一经用于正式快照或建议，不允许静默修改历史记录。后续修正通过新版本生效。

### 4.4 生成采购与供应建议

系统基于版本化规则或统计模型计算：

- 当前库存可支撑天数和预计缺料日期。
- 在途到货能否覆盖期间需求。
- 建议下单日期、最晚下单日期和建议数量。
- 安全库存不足、异常消耗、积压和外部价格变化风险。
- 可选供应商及其交期、最小订购量和外部变化依据。

建议必须保存输入快照、算法版本、参数、原因码和计算过程。AI 负责把计算结果与外部信号组织成可读解释，不得直接生成不可复现的数量，也不得自动创建采购订单。

用户可以批准、调整或拒绝建议，并填写调整值和原因。所有决策进入审计记录。

### 4.5 日报、周报和月报

`DAILY`、`WEEKLY` 和 `MONTHLY` 是报告周期，不是临时采集策略：

- 日报读取当日已固化的内部快照、外部信号和采购建议，必要时由独立调度任务提前完成同步与采集。
- 周报读取对应自然周内已审核或已发布的日报结构化快照，不直接启动浏览器。
- 月报读取对应自然月内已审核或已发布的日报结构化快照，不直接启动浏览器。
- HTML、Markdown 和 DOCX 是展示产物；趋势计算使用结构化快照，不能反向解析 HTML 作为事实数据。
- 缺少日报时返回缺失日期和操作提示，不自动补采。只有用户明确选择“补生成缺失日报”或“重新采集来源”时才创建独立任务。

默认时区为 `Asia/Shanghai`。系统分别保存数据业务时间、采集时间、快照日期和报告分析区间。

### 4.6 报告审核和交付

- 报告草稿包含摘要、重点变化、缺料与积压风险、采购建议、外部信号和证据引用。
- 用户可以修改正文、查看来源、比较版本并重新生成单个章节。
- 人工修改的其他章节不能被单章节重生成覆盖。
- 审核通过后可导出 Markdown 和 DOCX；PDF、SMTP 和协作工具通知后续增加。

### 4.7 自定义分析

保留 `ResearchBrief` 作为补充能力，用于不适合固化为物料监控规则的临时专题分析。它可以引用平台已经采集的内部快照与外部证据，但不再是产品首页和首版主流程。

## 5. 功能范围

### MVP 必须实现

- 登录和 `ADMIN`/`EDITOR` 权限。
- 物料、供应商、库存、消耗、需求和在途订单的 Excel/CSV 导入与校验。
- 物料、供应商、别名和外部实体映射。
- 20 至 50 个 URL 的定时采集、页面快照、差异检测和失败重试。
- 价格、规格、可用性、交期和供应商事件抽取，附原始证据。
- 每日内部数据快照、外部信号集合和每日情报快照。
- 确定性缺料、积压、采购时间和数量建议。
- 建议审核、调整、拒绝和审计，不自动写回企业系统。
- 日报、周报、月报和自定义期间报告；周月报只聚合日报结构化快照。
- 报告编辑、引用溯源、人工审核、Markdown 和 DOCX 导出。
- 任务失败可重试或从失败节点继续，幂等重试不产生重复快照、建议或报告版本。

### MVP 后增强

- ERP、MES、WMS 和数据库标准连接器。
- RSS、开放 API、授权登录页面与复杂站点适配器。
- 多仓库、多单位换算、多供应商分配和高级需求预测。
- 供应商绩效评分、场景模拟和价格趋势预测。
- Elasticsearch 混合检索、图表编辑、PDF 导出和消息通知。
- 经审批的采购建议导出或受控写回接口。
- 自定义分析模板和历史报告规则抽取。

### 首版不实现

- 自动创建、审批或下发采购订单。
- ERP、MES、WMS 主数据管理和交易替代。
- 验证码、付费墙或访问控制绕过。
- EHS、法律、法规或合规结论的自动裁决。
- 任意代码式爬虫市场和无边界全网爬取。
- 单一行业的硬编码流程。
- 复杂部门审批链、商业化计费和跨区域高可用。

## 6. 质量与验收标准

- 同一业务快照或页面内容幂等重试不会重复入库。
- 所有正式外部信号都能查看原始页面证据、采集时间和内容摘要。
- 低置信度物料或供应商映射不会自动进入正式建议。
- 相同输入快照、参数和算法版本产生相同的建议结果。
- 每条建议展示库存、消耗、在途、交期、规则版本和外部信号依据。
- 用户可以批准、调整或拒绝建议，且历史输入和决策不可被覆盖。
- 周报和月报不会触发 `Collect`、内部同步或浏览器；缺少日报时展示缺失日期。
- 趋势计算使用结构化日报快照，不解析 HTML 作为事实来源。
- 关键结论至少关联一个内部快照或外部证据；推断内容明确标记。
- Markdown 和 DOCX 导出的章节、引用和人工修改保持一致。
- 新增连接器、采集器、模型供应商或工作流执行器不需要修改核心领域契约。
