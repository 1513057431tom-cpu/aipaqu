# 通用物料与供应情报平台

## Problem Statement

制造企业的物料、库存、消耗、在途订单和供应商数据通常分散在 ERP、MES、WMS 与表格中；价格、规格、供货状态、交期和供应商动态又散落在外部网站。采购、计划和管理人员需要人工拼接这些信息，难以及时判断缺料、积压、价格变化和合适的采购窗口。

项目需要解决的不是替代 ERP/MES，也不是面向某一个行业定制一套流程，而是建立一个通用情报层：持续汇聚内部经营数据与外部公开或已授权数据，形成可追溯的变化信号、采购建议和周期报告。

## Recommended Direction

将产品定位为“通用物料与供应情报平台”，核心链路为：

1. 从 ERP、MES、WMS、数据库或 Excel/CSV 只读同步物料、库存、消耗、需求、在途订单与供应商数据。
2. 对用户配置的供应商网站、价格站点、市场页面和新闻页面进行定时采集，保存原始证据、页面差异和结构化变化信号。
3. 把内外部数据映射到统一的物料与供应商主数据，生成每日结构化情报快照。
4. 使用确定性规则与统计模型计算库存可支撑天数、缺料风险、补货日期和建议数量。
5. 使用 AI 做内容抽取、实体辅助匹配、异常解释和报告撰写，不让 AI 直接决定采购数量或执行采购。
6. 由业务人员审核、调整或拒绝建议；日报消费当日快照，周报和月报只聚合已固化的日报快照。

## Key Assumptions

- 企业能够提供至少一种稳定的内部数据入口，首版可从 Excel/CSV 导入开始，再逐步增加标准连接器。
- 首批 20 至 50 个用户指定页面能够提供有业务价值的价格、规格、供货或供应商变化。
- 物料编码、名称、规格和供应商物料编码足以支撑“自动候选匹配 + 人工确认”的实体映射流程。
- 用户更需要可解释、可调整的建议，而不是由系统自动创建采购订单。
- 日级快照能够满足首版周报、月报和趋势分析的精度要求。

上述假设应通过 2 至 3 家试点客户、真实导入样本和至少两周连续采集验证。重点记录映射准确率、有效信号率、建议采纳率和误报原因。

## MVP Scope

- 登录、工作区与基础权限。
- 物料、供应商、库存、消耗、需求和在途订单的 Excel/CSV 导入。
- 物料与供应商主数据、别名和外部实体映射。
- 20 至 50 个公开或已授权 URL 的定时监控、页面快照、差异检测和证据留存。
- 价格、规格、可用性、交期和供应商事件的结构化信号抽取。
- 每日内部数据快照、外部信号集合和每日情报快照。
- 基于规则的缺料、积压、采购时间和采购数量建议，附输入快照、算法版本与原因码。
- 建议的审核、调整、拒绝和导出，不自动写回企业系统。
- 日报、周报、月报生成；周报和月报只读取日报结构化快照，不启动浏览器。
- Markdown 与 DOCX 导出，以及引用证据回溯。

## Not Doing

- 不在首版替代 ERP、MES、WMS 或采购执行系统。
- 不自动创建、审批或下发采购订单。
- 不把 EHS、法律或合规结论交给 AI 自动裁决。
- 不绕过验证码、付费墙、登录权限或其他访问控制；需要身份的站点采用用户授权和人工接管。
- 不做全网无边界爬取，也不承诺支持所有网站。
- 不把药厂、化工厂或其他单一行业规则固化为产品核心。
- 不在首版实现高级预测、供应商自动评分和 ERP 双向写回。

## Open Questions

- 首批试点客户主要使用哪些 ERP、MES、WMS，能够提供哪些导出字段和更新频率？
- 首批必须监控的外部站点、页面类型和登录方式是什么？
- 建议计算的默认时间范围、服务水平、安全库存和交期参数由谁维护？
- 同一物料存在多单位、多仓库和多供应商时，首版按什么粒度给出建议？
- 业务人员希望以任务、消息、邮件还是企业协作工具接收告警？
